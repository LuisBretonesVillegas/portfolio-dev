The blueprint item is "Configure and verify single area OSPFv2": neighbor adjacencies, point-to-point, broadcast (DR/BDR selection) and router ID.

## OSPF in a few lines

OSPF is a **link-state** interior gateway protocol. Each router describes its own links in Link State Advertisements (LSAs), floods them to every router in the area, and stores them in an identical **Link State Database (LSDB)**. Each router then runs Dijkstra's SPF algorithm on that database to compute the shortest path to every network.

- Administrative distance: **110**.
- Metric: **cost**, the sum of the outgoing interface costs along the path.
- Runs directly over IP (protocol number 89).
- Multicast addresses: **224.0.0.5** (all OSPF routers) and **224.0.0.6** (DR and BDR only).
- Area 0 is the backbone. In a single-area design, everything is in area 0.

In a single area I mostly deal with two LSA types: **Type 1 (Router LSA)**, generated by every router, and **Type 2 (Network LSA)**, generated by the DR of each broadcast segment.

## Router ID

Every OSPF router is identified by a 32-bit router ID written like an IPv4 address. It's chosen in this order:

1. The value set manually with `router-id`.
2. The highest IPv4 address of an **up** loopback interface.
3. The highest IPv4 address of an **up** physical interface.

The router ID is chosen when the OSPF process starts. If I change it afterwards, it doesn't take effect until I run `clear ip ospf process` (or reload). I always set it manually so that it's predictable and doesn't depend on which interfaces happen to be up at boot.

## Neighbors and adjacencies

Routers discover each other by sending **Hello** packets every 10 seconds on broadcast and point-to-point networks. The **Dead** interval (40 seconds by default, 4 x Hello) is how long a router waits without Hellos before declaring the neighbor down.

To become neighbors, two routers must match on:

- **Area ID**.
- **Subnet and mask** of the shared link.
- **Hello and Dead timers**.
- **Authentication** settings, if used.
- **Stub area flag**.

And also:

- Their **router IDs must be unique**.
- The interface must **not be passive** (a passive interface doesn't send Hellos).
- The **MTU** must match for the adjacency to reach Full. With an MTU mismatch they see each other but get stuck in ExStart or Exchange.

### Neighbor states

| State | What has happened |
|---|---|
| Down | No Hellos received |
| Init | Hello received, but my router ID isn't in it yet |
| 2-Way | Each router sees itself in the other's Hello. DR/BDR election happens here |
| ExStart | Master and slave decided (higher router ID is master) for the database exchange |
| Exchange | Database Description (DBD) packets summarise each LSDB |
| Loading | Missing LSAs are requested (LSR) and sent (LSU) |
| Full | LSDBs are synchronised |

The five OSPF packet types map to those states: Hello, DBD, LSR, LSU and LSAck.

## Network types and the DR/BDR

On a **point-to-point** network there are only two routers, so they simply become Full with each other. No DR is elected.

On a **broadcast** network (Ethernet, the default for Ethernet interfaces, even when only two routers share the link), a full mesh of adjacencies would scale badly, so the segment elects:

- A **Designated Router (DR)**, which every router becomes Full with, and which generates the Type 2 LSA for the segment.
- A **Backup Designated Router (BDR)**, which takes over if the DR fails.

All the other routers are **DROthers**. DROthers become Full only with the DR and BDR; between themselves they stay in **2-Way**, which is normal and not a fault.

### Election rules

1. Highest **interface priority** (`ip ospf priority`, default 1, range 0 to 255). Priority 0 means the router never becomes DR or BDR.
2. Highest **router ID** as the tiebreaker.

The election is **non-preemptive**. If a router with a higher priority joins later, it doesn't take over; the DR only changes when the current DR fails (the BDR is promoted and a new BDR is elected). In a lab, that means the order in which routers boot can decide the DR. To force a new election I change priorities and run `clear ip ospf process` on the routers.

On an Ethernet link between exactly two routers I can avoid the election and the wait altogether with `ip ospf network point-to-point` on both ends.

## Cost and reference bandwidth

The cost of an interface is:

```text
cost = reference bandwidth / interface bandwidth
```

The default reference bandwidth is **100 Mbps**, and the result can't go below 1. That gives:

| Interface | Cost with 100 Mbps reference | Cost with 10,000 Mbps reference |
|---|---|---|
| 10 Mbps Ethernet | 10 | 1000 |
| FastEthernet (100 Mbps) | 1 | 100 |
| GigabitEthernet | 1 | 10 |
| 10 GigabitEthernet | 1 | 1 |

With the default, FastEthernet, Gigabit and 10 Gigabit all cost 1, so OSPF can't tell them apart. The fix is to raise the reference bandwidth, in Mbps, **on every router** in the area so the costs stay consistent:

```text
R1(config)# router ospf 1
R1(config-router)# auto-cost reference-bandwidth 10000
```

I can also set a cost directly on an interface, which overrides the calculation:

```text
R1(config-if)# ip ospf cost 50
```

Note that `bandwidth` on an interface changes the value OSPF uses in the formula, but it doesn't change the real speed of the link.

If two paths to the same network have the same total cost, OSPF installs both and load balances (up to 4 paths by default, adjustable with `maximum-paths`).

## Configuration

### Worked example topology

Three routers share one Ethernet segment through a switch, and each one has its own LAN.

```text
   192.168.1.0/24     192.168.2.0/24     192.168.3.0/24
        |                   |                   |
     Gi0/1               Gi0/1               Gi0/1
      R1                  R2                  R3
     Gi0/0 .1            Gi0/0 .2            Gi0/0 .3
        |                   |                   |
        +--------------- SW1 -------------------+
                     10.0.123.0/24
```

| Router | Router ID | Gi0/0 | Gi0/1 |
|---|---|---|---|
| R1 | 1.1.1.1 | 10.0.123.1/24 | 192.168.1.1/24 |
| R2 | 2.2.2.2 | 10.0.123.2/24 | 192.168.2.1/24 |
| R3 | 3.3.3.3 | 10.0.123.3/24 | 192.168.3.1/24 |

Goals: R1 must be the DR, R2 the BDR, and R3 must never be DR or BDR. The LAN interfaces shouldn't send Hellos to the hosts.

### Option 1: `network` statements

The `network` command uses a wildcard mask and enables OSPF on every interface whose IP address falls inside that range. It **doesn't** advertise a network by itself; it selects interfaces, and OSPF advertises the subnets of those interfaces.

```text
R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1
R1(config-router)# auto-cost reference-bandwidth 10000
R1(config-router)# network 10.0.123.0 0.0.0.255 area 0
R1(config-router)# network 192.168.1.0 0.0.0.255 area 0
R1(config-router)# passive-interface gigabitEthernet 0/1
R1(config-router)# exit
R1(config)# interface gigabitEthernet 0/0
R1(config-if)# ip ospf priority 100
```

A narrower option is to match each interface address exactly with a `0.0.0.0` wildcard, for example `network 10.0.123.1 0.0.0.0 area 0`.

### Option 2: interface configuration

The same result, configured per interface. I find it easier to read because each interface says explicitly which area it's in.

```text
R3(config)# router ospf 1
R3(config-router)# router-id 3.3.3.3
R3(config-router)# auto-cost reference-bandwidth 10000
R3(config-router)# passive-interface gigabitEthernet 0/1
R3(config-router)# exit
R3(config)# interface gigabitEthernet 0/0
R3(config-if)# ip ospf 1 area 0
R3(config-if)# ip ospf priority 0
R3(config-if)# interface gigabitEthernet 0/1
R3(config-if)# ip ospf 1 area 0
```

R2 is configured the same way with router ID 2.2.2.2 and default priority. With priorities 100, 1 and 0, R1 becomes DR, R2 BDR and R3 DROther. Without changing any priority, R3 would become DR and R2 BDR because of the router IDs, assuming all three start at the same time.

A useful alternative to listing passive interfaces one by one is to make them all passive and enable the ones that need neighbors:

```text
R1(config-router)# passive-interface default
R1(config-router)# no passive-interface gigabitEthernet 0/0
```

### Advertising a default route

If R1 also has an Internet link, it can inject a default route into OSPF:

```text
R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1
R1(config)# router ospf 1
R1(config-router)# default-information originate
```

R2 and R3 then learn it as `O*E2 0.0.0.0/0`. Without a default route in its own table, R1 doesn't originate one, unless `always` is added.

## Verification

### `show ip ospf neighbor`

On R1, the DR:

```text
R1# show ip ospf neighbor

Neighbor ID     Pri   State           Dead Time   Address         Interface
2.2.2.2           1   FULL/BDR        00:00:36    10.0.123.2      GigabitEthernet0/0
3.3.3.3           0   FULL/DROTHER    00:00:31    10.0.123.3      GigabitEthernet0/0
```

The state column shows both the adjacency state and the neighbor's role on that segment. If a fourth router with default priority joined, R3 would see it as `2WAY/DROTHER`.

### `show ip ospf interface brief`

```text
R1# show ip ospf interface brief
Interface    PID   Area            IP Address/Mask    Cost  State Nbrs F/C
Gi0/1        1     0               192.168.1.1/24     10    DR    0/0
Gi0/0        1     0               10.0.123.1/24      10    DR    2/2
```

Cost 10 confirms the new reference bandwidth on a Gigabit interface. `F/C` is Full neighbors versus total neighbors. The passive Gi0/1 has no neighbors but is still advertised.

### `show ip route ospf`

On R3:

```text
R3# show ip route ospf
...
O     192.168.1.0/24 [110/20] via 10.0.123.1, 00:04:12, GigabitEthernet0/0
O     192.168.2.0/24 [110/20] via 10.0.123.2, 00:04:12, GigabitEthernet0/0
```

`[110/20]` is administrative distance / metric: R3's Gi0/0 (cost 10) plus R1's or R2's Gi0/1 (cost 10).

### Other commands I use

```text
R1# show ip protocols
R1# show ip ospf interface gigabitEthernet 0/0
R1# show ip ospf database
```

- `show ip protocols`: router ID, the `network` statements or interfaces in use, passive interfaces, reference bandwidth and routing information sources.
- `show ip ospf interface`: network type, cost, priority, DR and BDR, timers. This is where I check Hello/Dead mismatches.
- `show ip ospf database`: the Router (Type 1) and Net (Type 2) LSAs of the area.

## Troubleshooting checklist

When two routers don't become neighbors, I go through this in order:

1. Is the link up and can they ping each other? (`show ip interface brief`, `ping`)
2. Is OSPF enabled on that interface, in the same area? (`show ip ospf interface brief`)
3. Is the interface passive? (`show ip protocols`)
4. Do the subnet, mask, Hello and Dead timers match? (`show ip ospf interface`)
5. Are the router IDs unique? (`show ip protocols`)
6. Stuck in ExStart/Exchange: check the MTU on both sides.
